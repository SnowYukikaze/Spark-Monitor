# 二次开发指南

面向「我要改功能 / 改界面 / 加一款设备」的场景。全部是单文件级别的改动，
不需要读懂整个项目。

## 目录地图

```
my_devices.py            入口（只做 sys.path + main）
ez24g/
  app.py                 线程、刷新、热插拔、命令行、单实例
  config.py              配置读写（所有落盘的东西只在这里）
  model.py               Reading —— 界面只认这个结构
  hidapi.py              HID 枚举 / 读写（唯一碰 ctypes 设备的地方）
  devices.py             设备服务：读哪台、休眠怎么显示、上次读数兜底
  providers/             ★ 数据源：HID（2.4G / 蓝牙 HID）、经典蓝牙 HFP、BLE（WinRT GATT）
  syswin.py              开机自启、快捷方式、系统深浅色
  win32.py               DLL / 结构体 / 原型 / 消息常量
  protocols/             ★ 协议插件，一个文件一款设备
  capture/               USBPcap：pcap 解析、推断、提权 helper
  ui/
    theme.py             ★ 配色 / 字号 / 圆角 / 卡片高度
    cards.py             ★ 卡片长什么样
    panel.py             ★ 面板版式（LAYOUT 字典）
    widgets.py           按钮 / 勾选框 / 滚动条
    help.py              抓包向导（文案在 GUIDE 列表里）
    tray.py              托盘图标与消息循环
    icon.py              GDI 画电量圆环
    shadow.py            窗口外发光
tools/                   自检脚本（见文末）
```

数据流：

```
providers.enumerate_refs()  →  DeviceRef（HID 带 ifaces，蓝牙带 MAC）
      ├─ HID  → protocols.read_best()      （协议插件，一行没改）
      ├─ 经典蓝牙 → Hands-Free AG 节点的 PnP 属性（毫秒级，不需要 winrt）
      └─ BLE  → WinRT GATT 0x180F/0x2A19   （可选依赖，没装就降级提示）
   ↓
devices.read_hid() / devices.read_bt()  →  Reading（transport = hid / bt）
   ↓
TrayApp._readings → Panel.render() / Tray.sync_icons()
```

`app.py` 的刷新是**两段式**：HID 先出结果（快），蓝牙 GATT 随后补上（慢），
这样启动时不会因为蓝牙卡住而看不到 2.4G 设备。

## 一、加一款新设备（最常见）

在 `ez24g/protocols/` 新建一个 `.py`，写一个类，加 `@register`：

```python
# ez24g/protocols/mymouse.py
from ..hidapi import HidDevice, HidIface
from ..model import Reading
from .base import DeviceProtocol, register


@register
class MyMouse(DeviceProtocol):
    id = "mymouse"          # 配置里记录的就是这个 id
    name = "某某鼠标"
    priority = 60           # 越小越先试
    auto = True             # True = 每次刷新自动试；False = 只在 --vendor 下试

    def match(self, iface: HidIface) -> bool:
        # 尽量写窄：VID/PID 或 UsagePage，否则每次刷新都会白试一遍
        return iface.vid == 0x1234 and iface.pid == 0x5678 and iface.output_len >= 16

    def read(self, iface: HidIface):
        with HidDevice(iface.path, write=True) as dev:
            dev.drain()                      # 丢掉陈旧的输入报告
            dev.write_output(bytes([0x08, 0x01]) + bytes(14))
            rep = dev.read_input(16, 500)
            if not rep or len(rep) < 3:
                return None                  # 没读到就返回 None，让下一个协议接手
            return Reading(ok=True, level=rep[2],
                           source=self.name, raw=rep)
```

不用改任何别的文件——`protocols/__init__.py` 会自动 import 整目录。

调试：

```bat
python my_devices.py --protocols      :: 确认插件被注册、优先级对不对
python my_devices.py --scan           :: 看这台设备现在能不能读到电量
python my_devices.py --scan --vendor  :: 允许厂商协议（会向设备写数据）
```

注意事项：

- `read()` 里**不要抛异常**，失败返回 `None` 或 `Reading(ok=False)`；外面也会兜住。
- 写设备前先 `dev.drain()`，否则可能读到上一次的回复。
- 只能读、不要改设备设置（原项目的原则）。
- 电量是 5% 步进的设备，直接返回设备给的值，别自己插值。
- 私有协议加密 / 需要握手的，抓包也拿不到，别硬试。

不想写代码也行：跑程序 → 插入设备 → 卡片上点「点我解决」→ 按向导抓包。

## 二、改界面

### 配色 / 字号 / 圆角

只改 `ez24g/ui/theme.py`：

```python
DARK = Theme(
    name="dark",
    pal=Palette(
        window=(27, 27, 28),      # 窗口底色
        card=(33, 33, 35),        # 卡片底色
        ...
    ),
    card_h=122,                   # 卡片高度
    card_gap=12,                  # 卡片间距
    radius=16,                    # 窗口圆角
    card_radius=12,               # 卡片圆角
    level_high=60,                # 电量 >= 60 用 ok 色
    level_low=30,                 # 30~59 用 warn 色，< 30 用 low 色
)
```

加第三套皮肤：照抄一个 `Theme(...)` 改名，在 `get_theme()` 里返回它。

### 卡片内容 / 版式

`ez24g/ui/cards.py` 的 `render_card()` 一个函数画完整张卡。
想加「充电中」标签就在电量数字下面 `cv.create_text(...)`；想换成横向布局就改
那几个坐标。窗口尺寸和滚动范围会自动跟着 `theme.card_h` 走。

### 面板结构

`ez24g/ui/panel.py`：

- `LAYOUT` 字典：标题位置、卡片左右边距、列表上下边界、底部三个元素的位置
- `_build_header()`：标题 + 副标题（点副标题或右侧「设置」手填刷新秒数，30–1800）
- `_build_list()`：滚动与卡片循环
- `_build_footer()`：更新时间 / 开机自启
- `_build_header()`：标题、副标题 +「设置」、右上角 ✕ 退出 / − 隐藏

加一个按钮就是一行：

```python
Button(cv, t, self.S, 400, 360, 64, 24, "设置", self.open_settings).draw()
```

### 文案

- 抓包向导：`ez24g/ui/help.py` 顶部的 `GUIDE` 列表
- 状态词：`ez24g/model.py` 的 `STATUS_TEXT`

## 三、加功能

| 想加的东西 | 动哪里 |
|---|---|
| 新命令行参数 | `ez24g/app.py` 的 `main()` |
| 新的数据源（非 HID） | `ez24g/providers/` 新建模块，实现 `enumerate_refs()` / `read_ref()` |
| 新配置项 | `config.py` 加 getter/setter，`load_config()` 不用动（dict 直读） |
| 低电量弹通知 | `app.py` 的 `_check_full()`（照抄满电通知那段） |
| 记录电量历史 | `app.py::_worker()` 里把 `res` 追加到自己的文件；建议新建 `ez24g/history.py` |
| 右键菜单加一项 | `panel.py::_on_right_click()` |
| 托盘左键行为 | `ui/tray.py::_proc()` 的 `WM_LBUTTONUP` |
| 换托盘图标样式 | `ui/icon.py::make_battery_icon()` |

三条纪律：

1. **界面线程不读设备**。读设备一律在 `TrayApp._worker()` 的后台线程里，
   结果写 `_readings`，界面只读 `snapshot()`。
2. **落盘只走 `config.py`**。别在界面里直接 `json.dump`。
3. **加协议不要改 `devices.py`**，插件自己声明 `match()`。

## 四、配置格式

`%APPDATA%\SparkMonitor\config.json`（独立目录，不读取其它版本的配置）：

```json
{
  "devices":   [{"kind": "hid", "vid": 14139, "pid": 4728, "name": "鼠标"},
                {"kind": "bt", "addr": "DE:1B:B4:46:93:66", "name": "蓝牙键盘"}],
  "protocols": {
    "373B:1278": {"kind": "standard"},
    "046D:C547": {"kind": "captured", "offset": 7, "invert": false,
                  "requests": ["08 7D 72 02 00 01 07 01"]},
    "1234:5678": {"kind": "vendor", "id": "atk2"}
  },
  "names":     {"x373B1278": "我的鼠标"},
  "last":      {"x373B1278": {"level": 87, "ts": 1750000000}},
  "interval":  60,
  "usbpcap":   "C:////Program Files////USBPcap////USBPcapCMD.exe",
  "vendor_probe": true,
  "ignored_devices": ["x12345678"],
  "bt_manual": {"DE:1B:B4:46:93:66": {"kind": "fixed", "level": 85}},
  "bt_source": {"DE:1B:B4:46:93:66": {"kind": "hid", "fails": 0}}
}
```

- `devices[].kind`：`hid`（默认，旧配置只有 vid/pid 时也按它处理）或 `bt`（用 `addr`）
- `groups`：`{"g1": {"name": "G517 LS TKL", "members": ["x046DC547", "bt:..."], "prefer": "auto"}}`，
  同一台设备的多条链路合并成一张卡（组键 `g:g1`）
- `ui` 段（全部可选，缺省即默认）：
  - `title`：窗口标题；`pos`：窗口位置 `[x, y]`；`tray_hint_shown`：首次托盘提示标记
  - `card_order`：卡片在分区内的顺序（拖动排序写这里，新设备排末尾）
  - `card_bg`：`{"x046DC547": "card_x046DC547.png"}`，图片存在 `%APPDATA%\SparkMonitor\media\`
  - `app_bg`：整窗背景文件名（同目录）
  - `opacity`：`{"card": 100, "app": 100, "menu": 100}`，0–100（menu 缺省 = 100）
  - `colors_light` / `colors_dark`：`{"text": [r,g,b], "ui": [...], "battery": [...]}`
- `protocols` 里的 `kind` 三选一：`standard`（标准 HID 电量）/ `captured`（抓包学的）/
  `vendor`（哪个插件读到的，`id` 对应插件 `id`）
- `vendor_probe`：设置菜单「自动识别」的状态，**缺省 true**。关掉之后
  `read_best(include_manual=False)`，只跑带 `auto=True` 的协议和已学到的协议，
  不再对未命中设备做厂商协议试探。
- `ignored_devices`：右键删除过的设备键。删除时写入，`discover_extras` 和 `read_bt`
  都会跳过，避免「删了又自己冒回来」；只有「+ 添加设备」里手动选回来才 `unignore`。
- `bt_manual`：蓝牙手动绑定，键是 MAC。`{"kind": "fixed", "level": 0-100}` = 固定显示；
  `{"kind": "gatt", "service": "180F", "characteristic": "2A19"}` = 从指定位置读。
  自动链路全失败时才兜底，卡片状态写「手动」。
- `bt_source`：记住这台蓝牙上次靠哪条链路读到（`"hid"` = 蓝牙 HID 联动）。
  连续 2 次读不到会自动清掉记忆，回到默认优先顺序。

## 五、自检脚本

改完跑一遍，比手点靠谱：

```bat
python tools\verify_all.py                :: 一条命令跑完全部（推荐）
python tools\test_core.py                 :: 推断/配置/注册表/上次读数
python tools\smoke_tray.py                :: 托盘窗口 + GDI 图标 + 通知
<带 tkinter 的 python> tools\smoke_layout.py     :: 面板几何（不靠眼睛）
```

## 五点五、外观自定义怎么实现的

- `ui/customize.py`：Pillow 图片导入/裁剪/圆角/透明度合成都在这；PhotoImage 由 Panel 的
  `_img_cache` 持有（不持有会被 GC 回收变白）。合成结果按
  （文件, **mtime_ns+size**, 尺寸, 透明度, 底色）缓存——不带内容标识的话，
  同名文件换图后会永远命中旧图。
- 选图流程：`import_image()` 写临时文件 → `os.replace` 原子替换 → 校验大小 →
  返 `None` 时把具体异常记进 `last_error()`；调用方 `_img_cache.clear()`。
- 弹窗绘制：所有坐标用**逻辑像素**，`_Base._finish()` 里统一 `cv.scale("all", …)`。
  `cv.create_window` 不吃 scale，Entry 必须在 `_finish()` 之后用物理坐标建。
- 卡片背景 → `cards.render_card(bg_photo=...)`：先画背景图，再画圆角描边，最后文字；
  有背景图时**不画**矢量设备图标（图标属于背景层）。
- 软件背景 → `Panel._paint_app_bg()`；头部/底部用同一张图的裁片盖住滚动内容，
  避免出现上下两条纯色带。
- 透明度 → Canvas 不支持半透明，`customize.blend(前景, 底色, alpha)` 先算实色再画。
- 颜色 → `theme.with_colors(theme, data)` 返回新 Theme（Palette 是 frozen），
  不改 `theme.py` 里的常量；深/浅两套各存一份。
- 拖动排序 → 每张卡的 item 打 `card:{key}`；拖动只 `cv.move` 这个 tag，让位卡片按剩余
  距离 35% 缓动，松手才 `render()` 一次。
  - 动画链用 `_anim_gen[key]` 代际号：新动画 +1，旧链每帧校验，不符立刻退出。
    （不加会怎样：斜拖时同一张卡挂好几条 `after` 链，位移累加 → 卡片乱飞。）
  - `_dragging` 期间 `render()` 只置 `_render_pending`，松手补画一次；
    否则外部刷新会把卡片画回原槽位，而 `_drag_layout` 还记着旧坐标。
  - 顺序变化**不要**重置 `_scroll`，只 clamp。
- 菜单 → `ui/menu.py::PopupMenu`（Toplevel + Canvas + round region + 阴影）。
  亚克力只是尽力而为：Win11 部分版本会静默忽略，失败时退 `-alpha 0.96` +
  底色与面板背景按 `ui.opacity.menu` 混合，两条路都不会崩。

## 六、已知坑

- **不要在主线程读 HID**：单次读取最多阻塞 1~2 秒，界面会卡死。
- **`Reading.present` 和 `Reading.ok` 是两件事**：`present=False` 才是真没插；
  插着但读不到是 `present=True, ok=False, status="asleep"/"unknown_proto"`。
- **`stale=True` 表示这是上次的数值**，界面必须显示「上次更新 HH:MM」，别当实时值。
- 同一句柄上并发 `ReadFile` 和 `WriteFile` 会卡死进程，所以 `HidDevice` 开了两个句柄。
- 设备枚举里 `HIDI2C` / `ACPI` 是笔记本内置设备，`providers/hid.py` 已按产品名/父设备过滤。
- 经典蓝牙耳机没有 BLE 电量服务，Windows 把 HFP 上报的电量缓存在
  Hands-Free AG 节点的 `{104EA319-6EE2-4701-BD47-8DDBF425BBE5}, 2` 属性上，
  类型是 **DEVPROP_TYPE_BYTE（3）**，不是 BOOL（17）也不是 STRING。
  读法见 `providers/bt_system.py`；属性为空就代表设备没上报，不要拿上次值冒充。
- **蓝牙 BLE 只在 Windows 认为「已连接」时才读**：设备关掉/休眠时直接显示「未连接」，
  不会拿上次的缓存数字充数。判断依据是 `BluetoothLEDevice.connection_status`。
- WinRT 的 `IAsyncOperation` 没有超时参数，设备半死不活时会一直等（实测 7 秒以上），
  `providers/bt.py` 统一放到后台线程限时（枚举 4s / 单次读取 4s），超时就放弃这一轮。
- 厂商协议默认 `auto=False`：这些协议会向设备写数据，不适合每次刷新都跑一遍。

## 附：Windows 启动脚本的两个硬性要求

`启动.bat` 是双击入口，改它时必须守住两条，否则会出现「双击一闪而过、软件打不开」——这个坑真实踩过一次：

1. **必须保存为 CRLF 换行。**
   命令解释器逐行解析批处理，LF-only 时 `if (...)` / `for ... do (...)` 这类括号块会解析失败。
2. **只能写 ASCII 字符。**
   解释器按系统 ANSI（中文系统是 GBK）读取文件。UTF-8 中文注释会被拆错行，
   剩下的字节被当成命令执行，报「'xxx' 不是内部或外部命令」。

`tools/smoke_interact.py` 的 R21 节会检查这两点（CRLF、纯 ASCII、无 BOM、含 tkinter 探测）。
`.gitattributes` 里写了 `*.bat text eol=crlf`，保证从 GitHub clone 下来时换行不会被改回 LF。

自测方法：解压到任意目录，双击 `启动.bat` 应出现面板窗口；
或在命令提示符里执行它——没有报错、`%APPDATA%\SparkMonitor` 生成即正常。
