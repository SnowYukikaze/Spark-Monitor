# 验收清单

改完之后按这三层验，别只凭"看起来没问题"。

## 第一层：自动检查（一条命令，约 35 秒）

```bat
python tools\verify_all.py
```

它会依次跑：`compileall` → `test_core` → `smoke_layout` → `smoke_interact` → `smoke_tray` → CLI。
全部通过时输出长这样：

```
检查项                 结果          通过      耗时   备注
--------------------------------------------------------------------
compileall          PASS         0    0.5s
test_core           PASS       113    4.6s
smoke_layout        PASS        33    0.9s
smoke_interact      PASS       667   41.0s
smoke_tray          PASS        33    1.3s
CLI --help          PASS         0    0.6s
CLI --protocols     PASS        11    0.6s
--------------------------------------------------------------------
结论：全部通过。
```

判断标准（别被"通过了"三个字糊弄）：

- **通过数是硬的**：113 / 33 / 667 / 33 是当前基线；少于基线会出警告——说明有用例被跳过或删了。
- **要有耗时**：0.0s 说明根本没跑。
- **失败会显示第一个 FAIL 行**，照着那行去看对应脚本里的断言。
- 想连真机读取一起验：`python tools\verify_all.py --full`（会调 `--once`，读真实设备）。

单独跑某一项（定位问题时用）：

```bat
python tools\test_core.py
<带tk的python> tools\smoke_layout.py
<带tk的python> tools\smoke_interact.py
python tools\smoke_tray.py
```

## 第二层：给新功能补断言（改完就写，别指望人眼）

现有四个脚本只覆盖已有功能。加了新功能，**必须补一条对应的断言**，否则下次改动没人能发现它坏了。

骨架（复制到 `tools/smoke_xxx.py`，再挂进 `verify_all.py` 的列表）：

```python
import os, sys
ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
sys.path.insert(0, ROOT)
import ez24g.app as A
A.UI_SCALE = 1.0
app = A.TrayApp(panel_only=True)
from ez24g.ui.panel import Panel
p = Panel(app)
p.show(); p.root.update()
# ...断言...
p.close()
```

三个现成写法：

**① 悬浮窗：尺寸与开关**
```python
p.set_mode("mini")                       # 你新加的方法
p.root.update()
assert p.W == 200, p.W                  # 逻辑宽度
assert p.root.winfo_width() == int(200 * p.S)
p.set_mode("panel"); p.root.update()
assert p.W == 760
```

**② 透明度：写配置并读回**
```python
p.set_alpha(0.6)
p.root.update()
assert abs(float(p.root.attributes("-alpha")) - 0.6) < 0.01
assert config.load_config()["ui"]["alpha"] == 0.6
```

**③ 蓝牙卡片：假数据 + 查画布文字**
```python
app._readings = {"bt:AA:BB:CC:DD:EE:FF": Reading(
    ok=True, level=63, name="MX Master 3S", transport="bt")}
p.render(); p.root.update()
texts = [p.cv.itemcget(i, "text") for i in p.cv.find_all()
         if p.cv.type(i) == "text"]
assert any("蓝牙" in t for t in texts), texts
```

几何类问题沿用 `smoke_layout.py` 的办法——量 `p.cv.bbox(item)`：
元素是否越界、卡片是否重叠、文本是否超宽、遮罩 z 序是否正确。

## 第三层：人眼 30 秒（自动检查证明不了"好看"）

**第十轮两条专项（必看）**

0a. 滚动条：按住右侧细条上下拖，卡片跟手滚动、**窗口不动**；松手后再动鼠标不会继续滚；点轨道空白翻一屏；光标变上下箭头。
0b. 静止背景：把软件背景透明度调到 40–60%，然后在面板背后拖动另一个窗口 / 播放视频 —— **不动本程序**，面板背景应当自己跟着变（本机约 17–20fps，约 50–100ms 的跟随延迟）。
0c. 截图：用 Win+Shift+S 或微信截图拍面板 —— **拍不到本程序窗口**（拍到的是它背后的桌面）。这是全屏抓屏排除的定义行为，不是 bug。

**设备管理（第十一轮修复，必看）**

0e. 冷启动：双击 `启动.bat` 后 3 秒内，面板要么已经出卡片，要么写「正在读取设备…」——**不该出现「还没有设备」**（那是首轮没读完时的误报）。
0f. 刷新：点「立即刷新」，按钮立刻变「读取中…」，几十毫秒内 2.4G 卡片先出来，1~3 秒内蓝牙补齐。刷新进行中再点一次，副标题会出现「已排队再刷一次」，本轮结束后自动再刷。
0g. 蓝牙断开：把耳机/键盘关机，**20 秒内**它的卡片变成「未连接（已关机或超出范围）」并沉到下面；不会再顶着旧电量排在第一位。
0h. 蓝牙数量：只连两台蓝牙时，面板上应当是两张卡。多出来的那张一定是"以前添加过、现在没连"的设备（卡片会写「未连接」），右键删除即可。
0i. 右键蓝牙卡片（不论它是 `bt:` 还是 `VID:PID` 键）都应有「手动绑定电量…」；填 85 后卡片状态写「手动」，留空取消。


**通用**
1. 面板 760×560、两列卡片、四角圆角正常，背后有柔和阴影。
2. 标题、副标题、卡片、底栏没有互相压字；没有文字被卡片边缘切掉。
3. 深色/浅色各看一次（Windows 设置里切主题，程序会自动跟随）。
4. 拖标题栏能移动，拖完阴影跟着走（不残留旧位置的影子）。
5. 点副标题或右侧「设置」都能弹出「每多少秒刷新」输入框，填 120 后副标题立刻变、重启保持；取消不改。
5b. 拖动卡片：同区内换位松手后顺序保持；跨区拖动会弹回并抖动；拖动时别的卡是滑过去的。
5c. 点卡片设备图区域能换背景图，名字/型号/状态/电量仍在图上面；右键可恢复默认背景。
5c2. 连换 3 张不同的图（卡片 / 软件各一遍），每次界面立刻变；重启后仍是最后那张。
5d. 设置 → 自定义背景 / 透明度 / 颜色三个弹窗都能实时预览，重启后保持。
5e. 150% 缩放下三个弹窗内容铺满、右下没有空白块；点滑块左/中/右分别得 0/50/100。
5f. 拖滑块时窗口不动（只有标题区能拖）；拖「软件背景」只改软件那一档。
5g. 拖色相条不卡；RGB 输入 255/0/0 → 预览变纯红、marker 跳到右上。
5h. 所有菜单都是圆角无系统边框，贴屏幕右下角时会往左上翻转；点外面 / Esc 都能关。
6. 双击设备名能改名，回车生效，Esc 取消；名字太长会截断不撑破卡片。
7. 右键卡片菜单能弹出、点空白能关掉。
8. 滚轮滚到底，卡片不会压到底栏按钮上。
9. 托盘图标数量 = 在线设备数；鼠标悬停 tooltip 有名称和电量。
10. 关闭再打开，窗口位置/大小/设置还在。

**悬浮窗（新增后）**
1. 切换后是 200 宽的小窗，不是被裁掉的大面板。
2. 整窗任意位置都能拖，拖到屏幕边缘不会被裁一半。
3. 透明度四档肉眼能分辨；调到 40% 时文字仍可读。
4. 双击能切回大面板，大面板尺寸/圆角/阴影正常。
5. 来回切 5 次，任务栏/托盘里不多出隐藏窗口。
6. 重启后仍在悬浮模式、透明度和位置都保持。

**蓝牙（新增后）**

0. 先跑 `python my_devices.py --scan`：第二段「蓝牙 BLE」要能看到设备，且状态是「已连接」时给出百分比；
   如果这里写「WinRT 不可用」，先 `pip install -r requirements-bt.txt`。
1. 与 Windows 设置 → 蓝牙和其他设备 里显示的电量对比，差值 ≤2%。
1b. 经典蓝牙耳机（HFP）：`python my_devices.py --scan` 第二段要出现耳机名，
   来源写「蓝牙 HFP（系统属性）」，数值与系统卡片一致；关掉耳机后变「未连接」。
2. 关掉设备电源 → 变「未连接」，**不能**继续显示上次数字。
3. 重新开机电量恢复，不需要重启程序。
4. 插着 2.4G 设备时，蓝牙设备也能同时显示，互不影响。
5. 没装 winrt 时，卡片给的是明确提示，不是空白或崩溃。

## 不能破的红线（任何改动后都要确认）

- 配置目录为 `%APPDATA%\SparkMonitor\`，不读取其它版本的旧配置。
- 托盘图标数量、左键刷新、右键开面板的行为不变。
- 刷新间隔、开机自启、单实例互斥仍然有效。
- 界面线程里没有阻塞式读设备（否则会假死）。
- 没有引入第三方依赖（除明确批准的可选依赖，如 winrt）。
- 125% / 150% 缩放下布局不错位（改 `set_mode` 改尺寸时最容易踩）。

## 已知的验证盲区（别浪费时间）

- **截屏全黑**：这个环境的桌面不可见，`CopyFromScreen` 拿到的是黑图。别用截图验收，用几何断言 + 人眼。
- **Tk 不报错 ≠ 布局对**：Canvas 画到窗口外不会抛异常，必须量 bbox。
- **线程静默死亡**：工作线程异常只会让界面停在旧数据，不会弹错。看 `--once` 是否还能读到值。
- **配置写坏不报错**：`save_config` 吞异常。改完开一次程序，确认 json 还能被解析。
- **高对比度模式**：系统开了高对比度时自绘颜色不跟随，属已知限制，别当 bug 修。

## 交付时让对方给你什么

让新会话交付时贴这三样，缺一样就说明没认真验：

1. `python tools\verify_all.py` 的**完整原始输出**（含通过数和耗时）。
2. 新增/修改了哪些文件（`git status --short`）。
3. 哪条红线它没法自动验、需要你手动确认（例如蓝牙真实电量对比）。
